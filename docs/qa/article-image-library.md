# Confirmed article-image collection

Base: multi-selection full candidate `041cdb4`. This is not yet published or browser-verified. The new local command recognizes an explicit image-library request, previews the current AI scope and requires **确认加入素材库** before any write. AI configuration is not required. Other text/layout instructions remain in the input and are not performed by this command.

## Data and scope contract

- No aiEdit/provider call for the local command; image URLs never enter its model prompt. Existing opt-in suggestions remain separate and off by default. Opening the collection preview immediately aborts an in-flight suggestion and suppresses queued/future suggestion requests while open. The suggestion-only context now replaces nested image references (including replay canvas/item images), without changing aiEdit context or ordinary prose links. Imported HTML is already converted to text slots by aiContext; this boundary does not strip arbitrary URLs from text.
- Selection validation uses the existing multi-subtree resolver. Empty, duplicate, absent and ambiguous IDs reject rather than falling back to the whole document. The collector visits actual selected blocks, not the extra parent/neighbor content in an AI context. Whole-document scope additionally includes the cover.
- Supported references: stored ImageRef objects, HTML img/data-src, SVG image href/xlink:href and inline CSS background URLs, including replay image/background references. Vector glyph outlines and generated rendered previews are not collected. Display-only wx-image proxies are restored to their source; remote query parameters are preserved.
- Collection never rewrites the document, creates a proposal, changes history, crops/swaps an image or alters replay/export output. Existing photos/animated-input best-frame behavior is preserved by calling the upstream saveAsset pipeline.
- The modal holds a document, synchronous document-change epoch and scope-token snapshot. Editing then undoing back to the identical document object does not revive an old confirmation. Changed document or selection ABA rejects confirmation; a change during a batch stops remaining items. Closing/unmounting stops future requests but **the current server request may still finish and create an asset**. This is not rollback or end-to-end cancellation. Already completed assets remain in the library.

## Server compatibility and security

The dedicated `/api/assets/import-article` returns a per-source imported/existing/failed result. Existing `/api/assets/fetch` and its URL-rewriting callers are untouched. Input validation rejects malformed lists, over 80 entries and URLs over 8192 characters; the UI uses one item per request for progress. The service admits at most 16 concurrent/queued requests and serializes them; the shared Sharp budget still applies. These limits are not a claim that overall process RSS/CPU is hard-capped.

Remote downloads use existing IMAGE_HOST and safeFetch unchanged: current host allowlist, DNS/IP pinning, redirect revalidation, size and header/body deadlines remain in force. Credentials in URL authority, arbitrary hosts, file/data URLs and arbitrary local paths are not imported. Transport errors produce non-sensitive generic diagnostics.

Successful remote imports store only a SHA256 sourceKey of the canonical full URL (query retained, fragment removed), not the original potentially signed URL. Repeated command requests consult that metadata and the actual file. This deduplicates this collection path, not historical assets imported through unrelated APIs without source metadata, and not different source URLs with identical pixel content. Index mutation remains the upstream mutateJson transaction; sourceKey is optional and existing saveAsset callers are unchanged.

Indexed `/media` variants reuse their original asset; query options do not trigger recropping. Existing regular `rp-<24 hex>.png` files are classified as managed replay glyphs, not newly added photo assets. Missing files and symlinks do not qualify as existing regular assets. Closing after an uncertain response can be retried; an already committed sourceKey prevents a second copy through this service. An independent concurrent deletion can still remove an asset after it was reported existing; this feature does not lock the entire library UI.

## Evidence and remaining gates

Collector/intent tests began 9 red, then green; an additional prohibition case was red before broadening explicit negative-word handling. Service tests began 10 red; real local HTTP route tests began 2 red/15 existing green, then passed with the route. Five real RightPanel confirmation tests were red before UI wiring, then green. Further tests cover in-flight close/unmount, double click, partial retry, real managed-glyph persistence and unchanged upstream upload/restore index interleaving.

Independent review found and reproduced document edit/undo ABA plus a pending/in-flight suggestion bypass at the direct collection entry: four added React tests were red before the epoch and suggestion suppression fixes. A fifth red test captured nested replay image URLs in the actual suggestion API payload; the suggestion-only boundary now removes those image references while preserving ordinary prose URLs and HTML text slots. The panel plus existing selection-sync integration group passed 28/28 after these fixes.

These are a **mixed** suite: pure functions, React/DOM/store integration, real HTTP and filesystem/Sharp integration with external/provider boundaries mocked. No strict-unit-only coverage percentage is claimed. Five new production modules (articleImages client/server, cssImageUrls, ArticleImageImport, suggestionContext) must be included in full-source coverage. There are no new dependencies.

Two real Windows browser scenarios are authored for offline natural language confirmation/content preservation and partial retry/close. Cloud browser execution is intentionally not attempted because the environment's launch restriction is already established. No real external image URL or model credential was contacted. Final post-review frozen-source validation: 107 mixed test files, 1109 passed and 2 skipped (106.86s), full ESLint, TypeScript and production build passed. Dev and packaged browser discovery each found 93 scenarios; discovery is not execution. The src/server SHA256 manifest matched before and after the serial run. The build retained the existing large-chunk warning. Independent review rechecked the document epoch and suggestion boundary without a remaining blocker. Actual Windows browser/portable gates remain outstanding.

This base predates the separate 44px touch-target follow-up and the current investigation of an existing photo drag/swap failure on the combined Windows candidate. These results do not claim that unrelated combined browser regression has been fixed or that this collection batch has run in a browser.
