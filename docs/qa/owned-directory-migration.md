# Owned portable directory migration (current manuscripts and linked history)

This is an intentionally narrow part of upstream directory migration, not a full restoration tool. A Windows portable application owner can set the process environment variable `XIUMI_LEGACY_MIGRATION_SOURCE` to an absolute local old checkout or its data directory before launching the executable. The ordinary web runtime is not enabled by that variable alone. The browser never sends or receives the path. Open 项目和素材备份 → 从本机旧目录迁移项目 → 检测已配置旧目录.

Detection reads bounded regular files, displays exact counts and does not write. Confirming applies once to the originally detected source version. Changed source data or a redirected target invalidates the preview; local destination records that arrive late are skipped without being overwritten. It uses the same manuscript, managed PNG/JPEG and add-only writer rules as ZIP restore. The reviewed source includes each supported history record for a source manuscript, the full asset index, and the exact bytes of referenced images, including those that appear only in history. A replacement, edit, or changed destination version folder requires a new detection. A snapshot can be added to a manuscript newly imported under the same confirmation, or to an existing local manuscript whose canonical content matches the source in all fields except its revision. The reviewed local revision must still match at confirmation, existing versions are not overwritten or evicted, and a history-only plan does not rewrite the manuscript. The migration skips same-ID divergent or unreadable manuscripts, and refuses to attach unrelated or orphaned destination history. The scoped writer does not import unattached history or large or complex layouts. A separate unchecked design option migrates supported custom themes, dependent templates and reusable components, with their indexed PNG/JPEG references. It does not require a source manuscript and uses the same validation and dependency/conflict rules as ZIP. A conflicting theme blocks its dependent templates, but unrelated components can still be added. Confirmation rechecks exact source record and eligible asset bytes, and source and destination folder identities. With a separate, unchecked-by-default independent-image option, it can also add qualified indexed PNG/JPEG images without a source manuscript. This uses the same byte validation and add-only ID/filename checks as ZIP restore. Preview reviews the source index and each eligible file; a post-preview byte or index change requires a fresh detection. It never imports unindexed files. It never reads .env or settings contents. Back up before migrating. The portable checks preserve portable path/file identity checks but are not an atomic defense against a concurrent process with hostile write access to the owner-selected directory tree.

Hosted integration:
- `pnpm exec vitest run tests/unit/legacyDirectoryMigrationRoute.test.ts tests/unit/legacyDirectorySnapshot.test.ts`
- Built browser, in an isolated test-owned data root and genuine upstream fixture: `pnpm build && pnpm e2e --config tests/owned-browser/playwright.config.ts`. This is separate from the ordinary dev proxy by design.
