# Xiumi 本机 MCP（第一批）

这一批对照上游的通用 MCP（`0c1f0cf530c59f9493e916f53afd0edf65a0a085`），使用本项目原有 HTTP API、DocOp 校验和项目保存版本机制。先启动 Xiumi 自己的服务（`pnpm dev` 或 `pnpm start`），再接入 MCP。它不自动启动，不对外监听，也不把本机 API 变成远程发布接口。

## 推荐：stdio

在仓库中运行 `pnpm mcp`。MCP 客户端的命令配置建议直接使用 Node，避免包管理器把提示信息混入协议标准输出：

```json
{
  "mcpServers": {
    "xiumi": {
      "command": "node",
      "args": ["--import", "tsx", "server/mcp/cli.ts"],
      "cwd": "/path/to/xiumi-ai-studio",
      "env": { "XIUMI_API": "http://127.0.0.1:5174" }
    }
  }
}
```

`cwd` 的设置因客户端而异；不能设工作目录时，从仓库目录启动客户端。Windows 路径要按客户端 JSON 规范转义。标准输入输出使用每行一个 JSON-RPC 消息；无 ID 的通知不会执行工具。

## 可选：本机 HTTP

只有显式传 `--http` 才启动 HTTP，默认端口 5175。先在当前终端中设置随机高熵 `XIUMI_MCP_TOKEN`（允许 16–256 个字母、数字或 `._~-`），再运行 `pnpm mcp --http 5175`。不要提交令牌或放进 Web 前端。在已有的本机服务上反向代理 MCP，会破坏它只供本机可信客户端使用的假设，因此不支持代理或共享端口。

- `GET /tools`：发现当前工具和参数。
- `POST /call/<工具名>`：用工具参数对象作为 JSON 请求体。
- `POST /mcp`：返回 JSON-RPC JSON，通知返回 202。此端点兼容上游的本机 JSON 形状，不宣称支持 SSE 或全套 MCP Streamable HTTP 会话协议。
- 每个请求都要提供 `Authorization: Bearer <令牌>`。仅接受本机主机名与实际侦听端口，不接受浏览器 Origin。单个请求最多 5 MB，批量 RPC 最多 16 条。
- `XIUMI_API` 只允许无路径的本机 IPv4 HTTP 地址（`localhost` 会归一化为 `127.0.0.1`），转发不追随重定向。

## 能力与差异

可以列出或读取项目、模块、素材、模板、组件、主题及历史版本；支持本地排版、新建空白项目、校验和应用 DocOp、保存版本、编译 HTML 与导出 Markdown。应用 DocOp 必须传刚读取到的 `revision`；默认只预览；只有明确传 `dry_run:false` 才保存非删除操作，不覆盖其他页面的新修改。删除文档模块也只允许预览。写操作只适用于得到授权的本机 Xiumi 库，建议先建测试库。

上传使用 `filename` 和 `base64`，最多 3 MiB，不接收主机文件路径。导出只把结果返回给调用者，不接受写文件路径。编译默认使用本机素材地址，显式传 `images:'embed'` 可内嵌本机光栅素材；重复引用也计入输出容量限制。主题列表包含自定义项，但本机 MCP 编译目前只保证内置主题和文稿已有的主题覆盖。保存版本沿用应用的每篇 50 个版本保留规则。MCP 不主动获取文稿中的外部资源。交由其他浏览器打开导出文稿时，应按文稿的来源和正文链接判断是否可信。

与上游首版相比，这批不提供模型外调、删除项目或推送公众号草稿箱工具，不是完整对齐。无需真实公众号、密钥或外部模型即可验收。
